# Этап 3 — безопасность и целостность данных

## Что реализовано

- персональный вход по `APP_PASSWORD` с защищённой HTTP-only cookie;
- proxy закрывает все страницы, API и server actions, кроме страницы и API входа;
- публичный просмотр push-журнала через `?log=1` удалён;
- частичный уникальный индекс БД не допускает две активные сессии одной тренировки даже при гонке запросов;
- удаление тренировки и каждого подхода требует подтверждения;
- каждая офлайн-операция получает постоянный UUID `operationId`;
- сервер сохраняет результат операции в `sync_ops`; повтор того же UUID возвращает сохранённый результат;
- на странице настроек добавлена полная JSON-резервная копия всех таблиц `public`.

## Настройка Vercel

Добавьте `APP_PASSWORD` в **Project Settings → Environment Variables** для Production, Preview и Development (по необходимости), затем выполните redeploy. Пароль не хранится в репозитории и не должен передаваться в чат.

## Идея безопасного импорта JSON

Импорт лучше делать отдельным этапом и только в два шага:

1. загрузка и проверка `format`, `version`, списка таблиц, типов колонок и внешних ключей без записи;
2. экран предпросмотра с количеством добавляемых/обновляемых строк и явным подтверждением, после которого весь импорт выполняется одной транзакцией.

Перед импортом следует автоматически создать свежую резервную копию. По умолчанию безопаснее поддерживать режим «восстановить в пустую БД», а режим слияния делать отдельно с явными правилами конфликтов по первичным ключам.
